| `fix(session): take over a quiescence claim whose holder stopped` | the settling of the row above lived only in the memory of the API process that held the claim, and a held claim was never reassigned, so a restart, a rollout or a crash of that process while it settled, or while its Pause or Quiesce was in flight, wedged the session again (giantswarm/kagent-upstream#175). The column comes with the core migration `000002_quiescence_claim_lease.sql`, because the line's released databases already hold `000001`; upstream folds schema changes into `000001` until its release, so the upstream version of the commit puts the column there.
