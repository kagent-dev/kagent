| `fix(adk): bound the bash tool by a configurable timeout and the turn` and `fix(adk): reap the background jobs a turn's end kills` | a coding agent's `git clone`, `fetch` or `push` of a real repository outlasts the fixed 30 s limit (60 s when the command mentions python), and a process one turn left in the background kept running into the next turn, which in a shared Session runs for another caller with that caller's credentials. The limit is now `KAGENT_BASH_TOOL_TIMEOUT` on the runtime (a Go duration, default 10m; the python rule is gone) and the tool's description tells the model the limit; the A2A executor records every process group a turn's commands started and kills what is still running when the turn ends, before the event that ends it is yielded, and reaps the killed processes it is the parent of: in a sandbox the runtime is PID 1, an orphaned background job is reparented to it, and unreaped it stayed a zombie that `pgrep` counts. Proven by unit tests and by the fork e2e on the `kagent` Harness (`TestBashToolEndsBackgroundJobsWithTheTurn`, `TestBashToolTimeoutFitsGit` against the git host fixture with a throttled path) | kagent-dev/kagent#3131 (open): the turn end and the reap, on top of kagent-dev/kagent#3006; the configurable timeout stays fork-only until kagent-dev/kagent#2357 settles its configuration surface |
